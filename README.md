# 리허설 (Rehearsal)

인생의 중요한 순간, 미리 한 번 해보기.

AI가 매번 다른 상황을 만들어 주고, 사용자가 실시간 음성으로 연습하며, 웹캠 비언어 분석과 함께 피드백받는 실전형 훈련 서비스. 도메인은 **면접, 금융사기 전화 대응, 연봉 협상, 임원 보고 Q&A, 병원 진료, 해외 입국 심사(영어), 보험 상담(상담사), 지인과 돈 이야기, 학부모 상담** 아홉 가지. 2026 해빗톤(9/14) 11팀 출품작.

## 1. 빠른 시작

```bash
npm install
cp .env.example .env      # ANTHROPIC_API_KEY 채우기. 비워두면 목업 면접관으로 동작
npm run dev               # 웹 http://localhost:5173 + API http://localhost:8787 동시 실행
```

- **크롬**에서 열어야 한다. 음성 인식(Web Speech API)이 크롬에서만 안정적이다.
- 첫 접속 때 카메라·마이크 권한을 허용한다.
- 맥북 내장 카메라·마이크로 동작한다. 시연 때는 외장 마이크 권장.

### 외부 공유 (ngrok)

```bash
ngrok http 5173 --url=regular-usefully-hen.ngrok-free.app
```

터널은 5173 하나만 열면 된다. `/api` 요청은 Vite 프록시가 8787로 넘긴다. 다른 ngrok 주소를 쓰면 `vite.config.ts`의 `TUNNEL_HOST`를 바꾼다. 카메라·마이크는 https에서만 열리는데 ngrok이 https를 제공하므로 휴대폰이나 다른 노트북에서도 바로 된다. 첫 접속 시 ngrok 경고 페이지에서 Visit Site를 눌러야 한다.

## 2. 사용자 흐름

```
홈 ─▶ 설정 (상황 선택) ─▶ 준비 ─▶ 세션 (최대 5분) ─▶ 리포트 ─▶ (예약) ─▶ 홈
                                                    └▶ 지난 리포트 (홈 최근 기록)
별도 화면: 관전 #watch=<userKey> · 관리자 #admin (새 탭)
```

1. **홈** — 이름 입력, 시작 버튼, 지표 3칸(연속 훈련 · 누적 훈련 · 최근 5회 평균 점수와 직전 5회 대비 ▲▼), 다음 예약, 최근 기록(클릭하면 지난 리포트). 최고 점수·평균 시선 유지는 상황 간 비교가 안 되고 과정 지표라 홈에서 뺐다(리포트에는 그대로).
2. **설정** — 상황 탭 9개(면접 / 금융사기 전화 / 연봉 협상 / 임원 보고 Q&A / 병원 진료 / 해외 입국 심사 / 보험 상담 / 지인과 돈 이야기 / 학부모 상담) 중 하나를 고르고 입력 칸을 채운다. 칸은 자유 텍스트이고, "랜덤으로"는 준비된 예시(도메인별 9~16개) 중 하나를 고른다. 상대의 성향과 돌발 변수, 사기 여부는 AI가 정하고 미리 알려주지 않는다. 홈에서 입력한 이름이 함께 실린다.
3. **준비** — 카메라 도메인: 카메라·마이크 권한 → MediaPipe 얼굴·자세 모델 로딩 → 3초 기준값 보정("화면 중앙을 평소처럼") → 동시에 시나리오 생성. 전화 도메인(금융사기): 카메라 없이 마이크만 열고 통화 카드로 진행하며 제목도 숨긴다(사기 여부 노출 방지). 시나리오 생성 진행 단계는 서버 WebSocket 이벤트로 실제 상태를 보여준다(풀에서 꺼냄 / 생성 중 / 완료). 준비되면 첫 대사 음성을 미리 요청해 둔다.
4. **세션** — 아래 루프가 돈다.
   - 상대(면접관·발신자·인사담당자·임원·의사·심사관)의 첫 말을 TTS로 읽는다.
   - 읽기가 끝나면 음성 인식이 켜진다. 말이 종결 어미로 끝났으면 1.0초, 아니면 1.6초 침묵에 발화가 확정된다. "답변 끝" 버튼으로 강제 확정 가능. 입국 심사는 STT·TTS 모두 영어.
   - 카메라 도메인은 확정 시점의 최근 30초 비언어 요약을 한 줄 붙여 서버로 보낸다.
   - 상대 응답이 SSE로 조각 단위로 오면 문장이 끝날 때마다 바로 읽는다(서버 TTS 스트리밍, 첫 소리 약 1초).
   - 응답에 `[END]`가 있으면 종료, 아니면 다시 듣기. 5분이 지나면 자동 종료.
   - **실전 모드**(준비 화면 토글, 브라우저에 기억): 오른쪽 패널·대화 기록·시선/자세 알약을 숨기고 화면(카메라 또는 통화 카드)만 크게 본다. 상대 아바타와 "말하는 중 / 내 차례"는 카메라 렌즈 바로 아래(위 중앙)에 놓아 상대를 보는 시선이 곧 카메라를 보는 시선이 되게 한다. 3초 카운트다운 뒤 상대가 말을 시작하고, Space는 답변 끝·말 끊기, Esc는 종료 확인이다. 세션 중에도 끄고 켤 수 있다. 리포트·홈·관리자 목록에 "실전" 배지가 붙고, 코치는 훈련자가 실시간 지표를 못 봤다는 전제로 비언어와 청취를 더 자세히 짚는다.
   - 상대가 말하는 동안 **"말 끊고 답하기"**를 누르면 재생을 멈추고 바로 듣기로 넘어간다. 응답이 아직 스트리밍 중이었다면 지금까지 나온 말만 "…"을 붙여 기록하고 스트림을 끊는다. 상대는 다음 턴에서 끊긴 것을 보고 자연스럽게 이어간다.
   - 카메라 도메인은 웹캠을 초당 15프레임(자세는 5프레임)으로 계속 분석해 시선 유지·자세 게이지를 갱신한다. 2초마다 진행 상태를 WebSocket으로 보내 관전·관리자 화면에 중계한다.
5. **리포트** — 세션 전체 대화, 지표, 이벤트 타임라인을 서버로 보낸다. 서버는 세션을 저장하고 큐에 넘긴 뒤 바로 응답하고, 화면은 "저장 → 전달 → 작성" 단계를 WebSocket으로 받아 표시한다. 완성되면 점수, 총평, 잘한 점, 보완할 점, 질문별 평가, 비언어 타임라인(카메라 도메인), 다음 훈련 제안이 채워진다. 여기서 다음 훈련을 예약할 수 있다.

입국 심사는 대화·음성 인식·음성 합성이 모두 영어로 돌고 리포트만 한국어다. 도메인 정의에 `lang: 'en'`을 주면 된다. 도메인 정의의 `usesCamera: false`는 전화 상황용이다. 카메라 권한을 요청하지 않고, 준비·세션 화면이 통화 UI로 바뀌며, 비언어 지표 없이 말한 내용만 평가한다. 현재 금융사기 전화만 해당.

도메인을 추가하려면: `src/lib/domains.ts`에 항목 하나(입력 필드, 프리셋, 문구), `server/domains/<id>.ts` 파일 하나(시나리오·상대·리포트 프롬프트, 목업), `server/domains/index.ts`에 한 줄, 지식베이스는 `server/cases/<id>.ts`. 나머지 코드는 도메인을 모른다.

### 실제 사례 기반 시나리오

시나리오 설계자와 코치 프롬프트에 실제 사례 지식베이스를 주입한다. AI가 지어내는 게 아니라 실제 수법·실제 질문을 변형한다.

사례는 `server/cases/`에 도메인별 파일로 둔다. 지식베이스의 대사는 구조와 전술의 예시이고, 프롬프트가 "문장을 그대로 복사하지 말고 기관명·직함·이름·금액·기한·순서를 매번 바꾸라"고 지시한다. 실측: 시그널플래너 사칭 사례를 넣었을 때 생성된 시나리오는 "보험금지원팀 박지영 상담원", "앱 조회 내역을 아는 척", "수수료는 환급금에서 돌려받는다"는 해명처럼 지식베이스에 없는 표현으로 같은 구조를 재현했다.

**공고·이력서 기반 면접**: 면접 탭에 "채용 공고"와 "내 이력서" 칸이 있다. 붙여넣기 또는 PDF·TXT 드롭(브라우저 안 pdf.js로 글자만 추출, 파일은 서버로 안 감, 각 6,000자 제한). 시나리오 설계자는 두 문서를 대조해 겹치는 강점은 검증 질문, 공고에만 있는 갭은 압박 질문, 이력서 수치는 측정법·기여분 추궁으로 만들고 첫 질문부터 이력서 항목을 인용한다. 면접관은 `resumeSummary`(5줄, 연락처 등 제외)와 `jdRequirements`를 알고 "이력서에 쓰신 ○○"으로 묻는다. 코치는 공고 요구사항마다 증명/부분/미답을 판정해 리포트 "공고 요구사항 대비" 표를 만들고 다음 훈련을 미답 항목으로 지정한다. **이력서 원문은 기록에 저장하지 않는다**(`store.saveSession`의 `stripDocs`가 길이 표시만 남김). 문서가 붙은 요청은 매번 고유하므로 시나리오 풀을 미리 채우지 않는다. 해빗팩토리 백엔드 공고 예시 버튼이 있다(가상 예시).

설계 원칙
- **영상은 기기를 떠나지 않는다.** 얼굴·자세 분석은 전부 브라우저 안에서 돌고, 서버로는 숫자 요약만 간다.
- **서버는 얇게.** API 키를 숨기고 프롬프트를 관리하는 프록시 역할만 한다.
- **어느 하나가 죽어도 데모는 이어진다.** 키가 없으면 목업 면접관, DB가 없으면 기록만 꺼짐, Redis가 없으면 캐시만 꺼짐, MQ가 없으면 리포트를 동기로 생성. 카메라가 없으면 음성 면접만, 음성 인식이 없으면 텍스트 입력으로.
- **로그인 없음.** 브라우저 localStorage에 기기별 사용자 키 하나를 두고 그 키로 기록을 묶는다. 이름은 홈에서 한 번 입력받아 같은 곳에 저장한다.
- **도메인은 두 파일에만 있다.** 클라이언트 `src/lib/domains.ts`와 서버 `server/domains/<id>.ts`. 라우트·워커·화면은 도메인 id를 하드코딩하지 않는다.

### Vite가 하는 일

Vite는 프론트엔드 개발 서버이자 빌드 도구다. 개발 중에는 React 코드를 브라우저에 즉시 반영하고(HMR), 배포 시에는 정적 파일로 묶어 `dist/`에 만든다. 이 프로젝트에서는 `/api` 요청을 8787의 Express로 넘겨주는 프록시 역할도 한다. 그래서 브라우저는 5173 하나만 알면 되고, ngrok 터널도 하나만 열면 된다.

## 5. 핵심 모듈 상세

### 5.1 비언어 분석 (`src/lib/vision.ts`)

MediaPipe Face Landmarker(얼굴 478점 + 회전 행렬 + 표정 계수 52개)와 Pose Landmarker(몸 33점)를 브라우저 GPU에서 돌린다.

| 지표 | 계산 | 판정 |
|---|---|---|
| 고개 방향 (yaw, pitch, roll) | 얼굴 회전 행렬에서 추출 | 기준값 대비 yaw 15°, pitch 15° 이내 |
| 눈동자 방향 (eyeH, eyeV) | `eyeLookIn/Out/Up/Down` 표정 계수 조합 | 기준값 대비 0.3 이내 |
| **시선 유지** | 고개 + 눈동자 조건 모두 충족 | 최근 30초 창에서 비율(%) |
| 미소 | `mouthSmileLeft/Right` 평균 | 0~1 |
| 어깨 기울기 | 양 어깨(11, 12) 각도 | 기준값 대비 8° 이내. 어깨 신뢰도 0.6 미만이거나 화면 밖이면 판정 안 함 |
| 웅크림 | (어깨 중심 y − 코 y) / 어깨 너비 | 기준값의 75% 미만이면 이탈. 보정 중 어깨가 절반 이상 안 보였으면 자세 판정 전체를 끔 |
| 얼굴 접촉 | 손목(15, 16)과 코 거리 < 어깨 너비 × 0.55 | 0.5초 이상 지속 시 이벤트 |

- **기준값 보정**: 시작 3초간 평균을 저장하고 이후 모두 편차로 판정한다. 안내는 "카메라"가 아니라 **"화면 중앙을 평소처럼"** 보게 한다. 훈련 중 실제로 보는 곳(상대 말풍선)이 기준이어야 하기 때문. 렌즈를 보고 보정하면 훈련 중 내내 아래를 보는 것으로 잡힌다.
- **떨림 방지**: 지수이동평균(α=0.25) + 상태 전환은 시선 연속 8프레임(0.5초), 자세 연속 15프레임(1초) 이상일 때만.
- **이벤트**: 시선 이탈 2초 이상, 자세 이탈 1.5초 이상, 얼굴 접촉 0.5초 이상을 타임스탬프와 함께 기록. 리포트의 타임라인 근거가 된다.
- **한계**: "카메라를 향하고 있는가"를 잡는다. 화면 어느 좌표를 보는지는 아니다. 리포트에서도 "카메라 응시 비율"로 표현한다.

### 5.2 음성 (`src/lib/speech.ts`)

- **STT** `listenOnce`: 크롬 Web Speech API, 도메인 언어(`ko-KR` / `en-US`), continuous + interim. 텍스트가 들어온 뒤 침묵이면 확정(아래 "침묵 감지"). 크롬이 자체 종료하면 텍스트 없을 때 재시작.
- **TTS** `Speaker`: 스트리밍 델타를 `push()`로 받아 문장 종결 부호(. ? ! 다. 요. 까? 죠?)에서 잘라 큐에 넣고 순서대로 재생한다. 전부 끝나면 `onEnd`.
  - **서버 모드(기본)**: 문장이 큐에 들어오는 즉시 `/api/tts`로 mp3를 미리 받아두고(prefetch) 순서대로 재생한다. 서버는 프록시의 `gpt-4o-mini-tts`를 호출한다.
  - **도메인별 목소리·말투** (각 `server/domains/<id>.ts`의 `voice`): 면접관 nova(차분·단정), 사기 전화 shimmer(콜센터 톤, 유창·서두름), 연봉 협상 상대 coral(부드럽고 프로페셔널), 임원 onyx(낮고 단호), 의사 alloy(빠르고 사무적), 심사관 ash(brisk American English). 말투는 `instructions`로 준다. 지시문은 톤을 바꾸지만 길이는 거의 안 바뀐다.
  - 속도 조절(`speed` 파라미터, 배속 버튼)은 시험 후 뺐다(2026-09-11). 필요하면 `speed`는 작동한다(1.3 → 7.5초→5.7초).
  - **스트리밍**: 프록시의 일반 경로(`/v1/audio/speech`)는 음성을 전부 만든 뒤 한 번에 내려준다(첫 바이트 ≈ 완료, 432자에 8.9초). 대신 **`/openai_passthrough/v1/audio/speech`에 body `"stream": true`**를 넣으면 LiteLLM이 OpenAI 응답을 그대로 흘려보낸다. 첫 바이트 0.9~1.0초, 이후 생성되는 대로 도착. 서버는 조각을 받는 즉시 클라이언트로 넘기고, 클라이언트는 MediaSource(`audio/mpeg`)로 첫 조각부터 재생한다. MediaSource가 mp3를 지원하지 않는 브라우저는 전체 수신 후 재생으로 폴백. 그 위에 아래 보조 장치가 있다. (1) Redis 캐시로 같은 문장은 즉시, 풀을 채울 때 첫 대사를 미리 생성, 준비 화면에서 첫 대사를 선요청. (2) 첫 문장이 길면 쉼표·접속어에서 한 번 먼저 잘라 첫 소리를 빨리 낸다. (3) 브라우저 음성으로의 전환은 사용자 UI 없이 서버 환경변수 `REHEARSAL_TTS=browser`로만 한다(디버그용으로 localStorage `rehearsal.tts=browser`도 동작). 캐시된 반응어("아, 네")를 먼저 틀어 대기를 덮는 방식은 시험했다가 어색해서 뺐다(2026-09-11). 상대가 스스로 말하는 "네," 는 그대로 둔다.
- **침묵 감지**: 인식된 문장이 종결 어미(다·요·까·니다 등)로 끝나면 1.0초, 아니면 1.6초 기다린다. 말 중간에 쉰 것과 끝난 것을 구분한다.
  - **브라우저 모드**: `REHEARSAL_TTS=browser`이거나 서버 TTS 요청이 실패한 문장은 SpeechSynthesis로 읊는다. 크롬의 Google 한국어 음성 → 맥 Yuna 순으로 고른다.

### 5.3 말투 측정과 화법 프로필

**측정**(`src/lib/speech-metrics.ts`): 세션이 내 발화마다 `timing`(듣기 시작→첫 소리 지연, 첫 소리→확정 시간, 텍스트 모드 여부)을 기록하고, 대화 기록만으로 첫 반응 지연, 말 속도(분당 글자수, 영어는 wpm), 답변 길이(글자·초), 필러("어·음·그·약간·일단…"), 완충 표현("~인 것 같아요·아마·혹시"), 단정 표현("무조건·절대·보장"), 문장 완결률(끝맺음 어미 vs 연결어·말끝 흐림), 존댓말·반말 혼용, 되묻기 횟수를 계산한다. 브라우저(리포트 카드)와 서버(코치)가 같은 파일을 쓴다. 크롬 음성 인식이 "어·음"을 자주 걸러내므로 필러 수는 과소 측정이고, 카드에 그 점을 표시한다.

**화법 프로필**(`server/cases/speech-style.ts`): 상황·회사 유형별 "좋게 보는 것 / 감점 신호 / 권장 속도·답변 길이·첫 반응 지연". 면접은 회사 유형 텍스트로 고른다: 은행·보험·금융 → 금융권형(담백한 사실, 완결된 문장, 일관성. IBK기업은행 인사담당자 "근거가 약해도 문장을 끝맺어라"), 스타트업·토스·카카오·해빗팩토리 → 스타트업형(솔직·직설, "잘 모릅니다" 인정, 의견+근거), 삼성·현대·공공 → 대기업형(결론 먼저, 간결, 허세 없음), 그 외 공통형(두괄식, 60~90초). 연봉 협상·임원 보고·병원·입국·사기 대응·보험 상담은 도메인별 고정 프로필이다. 한국어 권장 속도는 발표 표준(분당 350~450자)보다 느린 300~400자.

**리포트**: 점수 카드 아래 "말투와 전달" 카드에 첫 반응·말 속도·답변 길이·말버릇 4칸과 프로필 한 줄, 코치의 `speech` 코멘트(숫자 + 인용)가 나오고, 항목별 배점에 "전달(말투)" 항목(10~15점)이 들어간다.

### 5.4 비언어 → 면접관 연결

사용자 발화 텍스트 뒤에 한 줄을 붙여 보낸다.

```
[비언어 · 최근 30초] 시선 유지 42% / 자세 이탈 2회 / 얼굴 접촉 0회 / 미소 0.08 / 시선 이탈 최장 5초
```

면접관 시스템 프롬프트는 이걸 "시스템이 준 관찰 정보"로 취급하고, 숫자를 직접 말하지 않되 성향에 맞게 반응하도록 지시한다. 배려형이면 "천천히 답하셔도 됩니다", 압박형이면 "확신이 없어 보이시는데요". 실측에서 시선 유지 38%를 보내자 냉철한 리드 성향 면접관이 "확신이 없어 보이시는데요"로 시작했다.

### 5.5 서버 프롬프트 (`server/domains/`)

라우트와 워커는 도메인 내부를 모른다. `server/domains/index.ts`의 조립 함수 세 개만 부른다: `buildDesignerSystem(dom, fields)`(시나리오 설계자), `buildCounterpartSystem(dom, scenario)`(대화 상대), `buildCoachSystem(dom, log)`(코치). 각 함수는 도메인 프롬프트에 해빗팩토리 사내 규칙과 훈련자 이름 규칙을 이어 붙인다. 도메인별 목소리(`voice`)와 언어(`lang`)도 도메인 정의에 있어서 `/api/tts`와 첫 대사 선합성이 그것을 읽는다. `server/index.ts`에는 도메인 id 하드코딩이 없다.

도메인마다 세 개의 프롬프트가 있다. 아래는 면접 기준이고, 금융사기 전화는 같은 구조에 발신자·코치 프롬프트가 들어간다.

| 엔드포인트 | 모델 | 출력 | 핵심 지시 |
|---|---|---|---|
| `/api/scenario` | opus-4-8, effort low | JSON: title, interviewer{name, style}, opening, hiddenPlan | 매번 다른 성향과 돌발 변수 1~2개. hiddenPlan은 사용자에게 비노출 |
| `/api/turn` | sonnet-4-6 | SSE 텍스트 스트림 | 구어체, 두 문장 이내, 답변에 한 번 반응 후 다음 질문, 4~5턴 뒤 `[END]` |
| `/api/report` | fable-5 → 실패 시 opus-4-8 | JSON: score, headline, strengths, improvements, perQuestion, nonverbal, nextTraining, scoreBreakdown(항목별 max·score·근거, 합계 = score) | 구체적으로. 비언어는 타임라인 사실로. 성격·감정 단정 금지 |

모델 출력 JSON은 `parseJsonWithRepair`로 읽는다. 문자열 안 쌍따옴표 같은 문법 오류면 빠른 모델(sonnet)로 문법만 고쳐 한 번 더 파싱한다. 출력이 길어져 잘리면(공고·이력서가 붙은 시나리오, 배점·말투·커버리지가 있는 리포트) 복구 과정에서 뒷부분이 통째로 사라지므로 토큰 한도를 넉넉히 두고(시나리오 2000, 문서 있으면 4000 / 리포트 6000) 필수 필드(시나리오: title·opening·hiddenPlan·interviewer, 리포트: score·headline·strengths·improvements·nextTraining)가 없으면 실패로 던져 재시도·폴백으로 넘긴다. 설계자·코치 프롬프트 끝에는 "문자열 안 인용은 홑따옴표" 규칙이 붙는다.

### 5.6 저장소 (MySQL + Redis)

**MySQL** 스키마 `rehearsal` (서버 시작 시 없으면 생성)

| 테이블 | 내용 |
|---|---|
| `users` | user_key(기기 키), nickname(홈에서 입력한 이름), 첫 방문·마지막 방문 |
| `sessions` | 한 번의 훈련. domain, setup(fields에 name 포함)·scenario·turns·events·overall JSON, duration, 시선 유지 %, 점수, 리포트 JSON, 리포트 모델, report_status, client_id(UNIQUE, 중복 저장 방지) |
| `reservations` | 다음 훈련 예약. scheduled_at, 이행한 세션 id, 이행 시각. 예약 시각 앞뒤 90분 안에 훈련하면 자동 이행 처리 |

**Redis** db15, 키 접두어 `rehearsal:`

| 키 | 타입 | 용도 |
|---|---|---|
| `scenario:pool:{hash}` | LIST | 같은 설정으로 미리 만들어 둔 시나리오. LPOP으로 꺼내고 배경에서 2개까지 다시 채움. TTL 6h. **첫 호출 11초 → 이후 4ms** |
| `scenario:filling:{hash}` | STRING | 프리페치 중복 방지 잠금. TTL 60s |
| `tts:{hash}` | STRING | 문장별 mp3(base64). 같은 문장은 즉시. 풀 채울 때 첫 대사를 미리 생성. TTL 24h. **1.3초 → 7ms** |
| `streak:{userKey}` | STRING | 연속 훈련 일수 캐시. 세션 저장 시 무효화. TTL 1h |
| `live:{userKey}` | HASH | 진행 중 세션의 최근 30초 지표. 세션이 WS로 2초마다 보내는 것을 저장. 디버그용(`GET /api/live/:userKey`). TTL 10m |

**연속 훈련 일수**는 KST 기준으로 오늘(오늘 안 했으면 어제)부터 거슬러 하루도 빠지지 않은 날 수다.

**데이터 초기화** (시연 전 테스트 기록 정리). 스키마·테이블은 남기고 내용만 지운다.

```bash
mysql -h127.0.0.1 -uroot rehearsal -e "DELETE FROM reservations; DELETE FROM sessions; DELETE FROM users; ALTER TABLE sessions AUTO_INCREMENT=1; ALTER TABLE reservations AUTO_INCREMENT=1;"
redis-cli -n 15 --scan --pattern 'rehearsal:*' | xargs -r redis-cli -n 15 DEL
curl -s -u guest:guest -X DELETE http://localhost:15672/api/queues/%2F/rehearsal_rmq/contents
curl -s -X DELETE -H 'x-admin-token: rehearsal' http://localhost:8787/api/admin/live   # 관리자 "방금 끝난 훈련" (서버 메모리)
```

브라우저에 저장된 이름은 남아 있어 다음 접속 때 `users`에 다시 들어간다. 관리자 화면의 "방금 끝난 훈련"은 DB가 아니라 서버 메모리 레지스트리라 위 마지막 명령 또는 화면의 "목록 비우기"로 지운다(그냥 두면 마지막 신호 10분 뒤 사라진다).

### 5.7 리포트 비동기 처리 (RabbitMQ)

리포트 생성은 30초 안팎이 걸리는 유일한 무거운 작업이라 큐로 뺐다. 기존 로컬 큐 명명 규칙(`xxx_rmq` / `xxx_rmq_dlq`)을 따라 새 큐 `rehearsal_rmq`를 쓴다.

```
POST /api/report
  ├─ MQ·DB 살아 있음 → sessions에 report_status='pending'으로 저장 → rehearsal_rmq에 {type:'report', sessionId} 발행 → 12ms에 응답
  │     └ 워커(서버 프로세스 안, prefetch 2) → 세션 읽기 → 리포트 생성 → report/score/report_status='done' 갱신
  │           └ 실패 → 1회 재발행 → 또 실패 → status='failed' + rehearsal_rmq_dlq에 기록
  └─ MQ 없음 → 예전처럼 동기 생성 후 응답
```

완료는 **WebSocket으로 푸시**된다. 워커가 작업을 잡으면 `report_started`, 끝나면 `report_done`(리포트 본문 포함), 실패하면 `report_failed`(재시도 여부)를 해당 사용자 연결에 보낸다. 리포트 화면은 "저장 → 전달 → 작성" 3단계 표시를 서버 이벤트로 갱신하고, 홈과 지난 리포트 화면도 `report_done`을 받으면 자동 갱신한다. WS가 끊긴 경우에만 6초 폴링이 폴백으로 동작한다. 그래서 리포트 대기 중에 탭을 닫아도 리포트는 완성되어 홈의 최근 훈련에 남는다.

### 5.8 WebSocket (`server/realtime.ts`, `src/lib/ws.ts`)

경로 `/ws`. Vite 프록시(`ws: true`)와 ngrok을 통과한다. 클라이언트는 연결 후 `{type:'subscribe', userKey}`를 보내고, 끊기면 지수 백오프로 재연결한다.

| 메시지 (서버→클라) | 언제 | 쓰는 화면 |
|---|---|---|
| `report_queued` / `report_started` / `report_done` / `report_failed` | 리포트 큐 처리 단계 | 리포트(3단계 표시), 홈(목록 갱신), 지난 리포트 |
| `scenario_progress` (pool_hit / generating / done / pool_refilled / failed) | 시나리오 요청 처리 | 준비 화면 진행 문구가 실제 서버 상태를 반영 |
| `live_update` (metrics, turn/turns, phase, elapsedMs, title, counterpart, name, ended) | 훈련자가 보낸 `live` 를 관전자에게 중계 | 관전 화면 |
| `admin_update` (진행 중·방금 끝난 훈련 목록, sessionId·점수 포함) / `admin_denied` | 레지스트리가 바뀔 때 0.4초 디바운스 | 관리자 화면 |

| 메시지 (클라→서버) | 용도 |
|---|---|
| `subscribe {userKey}` | 본인 이벤트 수신 |
| `spectate {userKey}` | 다른 사용자의 훈련을 관전 |
| `live {...}` | 세션 중 1초마다 지표·상태·제목·최근 대화·말하는 중인 문장(`current`)·인식 중인 내 말(`interim`), 대사가 생길 때 즉시, 끝날 때 `ended`, 탭 닫힘 시 `left`(HTTP beacon). 서버는 Redis(`live:{userKey}`)에 저장하고 관전자·관리자에게 중계 |
| `admin {token}` | 관리자 구독. 토큰이 틀리면 `admin_denied` |
| `ping` | 25초마다 연결 유지 |

연결 전에 보낸 `live`는 클라이언트가 최대 20개까지 버퍼링해 연결 직후 순서대로 보낸다(늦게 들어온 관전자도 제목·대화를 바로 본다).

### 5.9 이름 · 사내 상황 · 입력값 · 관리자와 관전

**이름**: 회원 가입 없이 홈에서 이름을 한 번 입력받아 브라우저(`rehearsal.nickname`)와 서버 `users.nickname`에 저장한다. 준비 화면에서 `fields.name`으로 실려 시나리오 설계자("opening에서 한 번 부른다"), 대화 상대("이미 알고 있으니 묻지 않고 가끔 호칭"), 코치("리포트에서 OO 님")에게 들어간다. 호칭 규칙은 `shared.ts`의 `defaultNameNote()`가 기본이고, 도메인이 `nameNote`를 정의하면 그것을 쓴다(입국 심사는 여권 이름으로 Mr./Ms. + 로마자 성). 관리자·관전 화면은 키 대신 이름을 보여준다. 이름이 없으면 홈의 시작 버튼이 이름 입력으로 포커스를 옮긴다.

**해빗팩토리 사내 상황** (`server/cases/habitfactory.ts`): 입력값 어디에든 "해빗팩토리"·"시그널플래너"가 있으면 사내 상황으로 보고, 사용자를 상대하는 **한 사람만** 실제 인물로 세운다(면접은 직무별 리드·모바일 팀 리드·CSO·정보보호·경영지원 또는 대표, 연봉 협상은 대표(기본)·상황에 "인사"가 있으면 인사 팀장, 임원 보고는 대표·CTO·CSO·경영지원(재무)·정보보호·핀랩 CEO·핀랩 운영 리드). 그 외 인물은 익명, 사기 전화에서는 실명 금지, 톤은 전문적·존중, 회사 수치 단정 금지. 인물 명단은 이 파일에서 수정한다.

**입력값과 상대의 지식**: 준비 화면의 칸은 자유 텍스트다(랜덤은 도메인별 예시 9~16개 중 하나. 2026-09 기준 최신 소재: AI·LLM 엔지니어·DevOps 면접, 악성앱 전화 가로채기·AI 목소리 합성 사기, 영국 ETA·EU EES/ETIAS 입국 심사 등). 입력값은 시나리오 설계 프롬프트에 그대로 들어가고, 서버가 시나리오 응답에 `fields`로 다시 붙여 준다. 대화 상대 프롬프트에는 `knownFacts()`로 "상대가 알 법한 것"만 골라 넣는다: 면접관은 이력서 정보 전부, 연봉 협상 상대는 직무·현재 연봉만(희망 연봉·경쟁 오퍼는 사용자의 카드), 임원은 보고 내용 전부, 의사는 접수증의 주 증상만, 입국 심사관은 입국지만, 보험 상담의 고객은 자기가 신청서에 쓴 내용(상담사가 다시 물으면 살짝 짜증). 이미 들은 정보를 다시 묻지 않는다는 규칙도 함께 들어간다.

**관리자 화면 (`#admin`)**: 홈 오른쪽 위 "관리자"로 들어간다. 비밀번호는 `REHEARSAL_ADMIN_TOKEN`(기본 `rehearsal`), 브라우저에 기억된다. 서버가 WS `live` 메시지로 진행 중 훈련 레지스트리를 유지하고(`admin` 구독자에게 0.4초 디바운스로 `admin_update` 푸시, 10분 무신호 시 제거), 화면은 카드 그리드로 도메인·제목·경과 시간·진행 상태·시선 유지 %를 보여준다. 카드를 누르면 그 자리에서 관전 화면으로 들어가고, "방금 끝난 훈련"에는 리포트 상태와 점수가 실시간으로 채워지고, 세션이 저장된 뒤부터는 줄을 클릭해 리포트(작성 중이면 진행 화면)를 볼 수 있다(레지스트리 항목에 `sessionId`가 실린다). 아래 "전체 최근 기록"은 전체 사용자의 기록을 30건씩 보여주고(REST `/api/admin/sessions?limit&offset`, 총 건수 포함) "더 보기"로 이어 본다. 어떤 훈련이 끝났다는 `admin_update`가 오면 3초 스로틀로 목록을 다시 불러와 점수가 자동 반영된다. 줄을 클릭하면 그 훈련의 리포트(`/api/admin/sessions/:id`, 훈련자 키 표시)를 본다.

**관전 화면 (`#watch=<userKey>`)**: 관리자 카드의 "링크 복사"로 특정 훈련자의 관전 링크를 만들어 비밀번호 없는 다른 모니터에 넘길 수 있다(세션 화면에는 관전 버튼을 두지 않는다. 훈련자 화면은 훈련에만 집중). 훈련 화면이 1초마다 보내는 상태(지표, 최근 대화, 상대가 지금 말하는 문장, 훈련자의 음성 인식 중간 결과)를 받아 시선 유지 %와 대화가 실시간으로 자라고, 시계는 신호 사이를 로컬로 보간해 매초 움직인다. 훈련이 끝나면 "훈련 종료 → 리포트 작성 중 → 점수·총평"으로 이어진다. 훈련자가 종료 버튼 없이 탭을 닫거나 나가면 세션 화면이 `pagehide`에서 beacon으로 `left` 신호를 보내 관전 화면에는 "훈련자가 나갔습니다(저장 안 됨)", 관리자에는 "중단(나감)"이 뜬다. 15초 이상 아무 신호가 없으면(탭 백그라운드, 네트워크 끊김) 경고를 띄운다. 사용자 키는 전체가 표시된다(클릭 시 전체 선택).

시연 흐름: 발표 노트북에서 훈련, 심사위원 모니터에는 `#admin`을 띄워 두고 카드가 뜨면 클릭해 관전. 여러 명이 동시에 체험해도 목록에서 골라 볼 수 있다. 워커를 별도 프로세스로 빼고 싶으면 `mq.ts`의 `consume`을 다른 엔트리에서 호출하면 된다.

큐 상태 확인: `rabbitmqctl list_queues name messages consumers | grep rehearsal`

## 9. 2024 해봇과의 차이

2024 해빗톤 "해봇"은 신입 상담사가 AI 고객과 텍스트 채팅으로 보험 상담을 연습하는 사내 도구였다. 리허설은 다음이 다르다.

| | 해봇 (2024) | 리허설 (2026) |
|---|---|---|
| 대상 | 사내 신입 상담사 | 일반 사용자 + 상담사 (보험 상담 도메인) |
| 연습하는 것 | 어떤 고객을 만날지 | 어떤 상황이 닥칠지 (면접·사기 전화·협상·보고·진료·입국·상담) |
| 상대 설정 | 슬라이더로 직접 | AI가 랜덤 생성, 숨은 니즈·돌발 변수 비노출 |
| 채널 | 텍스트 채팅 | 실시간 음성 통화 (+ 카메라 도메인은 웹캠 비언어) |
| 지식 | 없음 | 2025~26 실제 제도·사례 지식베이스 (상담 도메인: 5세대 실손, 보험료 인상, 수수료 공시) |
| 피드백 | 텍스트 평가 | 항목별 배점과 근거, 컴플라이언스(필수 고지·단정 표현) 점검, 다음 훈련 지정 |
| 운영 | 1:1 | 관전·관리자 화면, 예약·연속 훈련, 기록 |

**보험 상담 도메인은 해봇의 발전형이다.** 같은 "상담사 ↔ AI 고객" 구조지만, 텍스트가 아닌 음성으로 실제 콜백 전화를 재현하고, 고객은 신청서 뒤에 진짜 사정을 숨기고 있어 질문으로 찾아내야 하며, 코치는 2026년 제도 사실과 금소법 설명의무 기준으로 상담사의 말을 검증한다. 시연에서 해봇을 아는 청중에게 "이렇게 발전했다"를 보여주는 장면으로 쓴다.

## 10. 알려진 제약

- 시선은 카메라 방향 기준이다. 화면 좌표 시선 추적은 아니다.
- 음성 인식은 크롬 내장 기능이라 소음에 약하다. 사파리·파이어폭스 미지원.
- 서버 TTS는 첫 소리까지 약 1초(스트리밍), 상대 응답 첫 토큰까지 1.1~1.4초라 사용자가 말을 끝낸 뒤 상대가 입을 열기까지 2초 안팎의 공백이 있다. 브라우저 폴백 음성은 기기마다 다르다.
- 시나리오 생성은 11~20초 걸린다. 같은 설정은 풀에서 즉시 나오지만 처음 보는 설정(이름 포함)은 준비 화면에서 기다린다.
- 해빗팩토리 실명 인물의 성향은 AI가 임의로 정한다. 실제 성격과 무관하며 사내 발표용이다.
- 조명이 어둡거나 카메라가 너무 낮으면 랜드마크 품질이 떨어진다. 정면 조명, 눈높이 카메라.
- 애플 실리콘 맥 크롬 기준으로 작성됐다. 저사양 기기에서는 `vision.ts`의 프레임 주기(66ms)를 늘린다.
